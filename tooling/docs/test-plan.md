## 0. Resolved first: the largest open risk

`architecture.md` §7 named this as the biggest threat to the design —
whether scipy could express the workspace's null models, or whether `stats`
would have to keep real statistical code and AD-3 ("borrowed computation,
owned policy") would weaken.

**Spiked and settled, by execution.** Reconstructing the null generically —
N ordered positions, a marker occupying k of them, each occurrence covering
±W, statistic = how many fixed target points fall inside the covered mask:

| Route | p-value | Verdict |
|---|---|---|
| The workspace's hand-rolled loop | **0.600570** | baseline |
| `scipy.stats.permutation_test` | — | **cannot express it** |
| `scipy.stats.monte_carlo_test` with a custom `rvs` | **0.600570** | **exact agreement**, difference 0.000000 |

`permutation_test` cannot express it because this null is not a relabelling
of observed data — there is no second sample and no pairing, so none of its
three `permutation_type` values apply. **`monte_carlo_test` expresses it
exactly**, uses the same `(k+1)/(n+1)` estimator, and reproduces the
hand-rolled p-value to the digit.

**Consequence, and it is a correction:** `libraries.md` and `requirements.md`
pointed at `permutation_test` as the replacement for the workspace's 8
`pval` copies. That is right for two-sample comparisons and **wrong for the
structural nulls**, which are the majority of S-04. The correct entry point
there is `monte_carlo_test`. AD-3 survives intact — `stats` stays a policy
wrapper — but over two scipy functions, not one.

## 1. How these tests are meant to fail

Every case below is written so that it fails **before** the code exists and
passes only once the requirement is met — steps 5 and 6 are test-driven.
Three rules learned the hard way in this repository:

1. **A test must be able to fail.** `verify.py` caught a fixture whose two
   halves were identical, so it asserted nothing. Every case here names what
   makes it non-vacuous.
2. **Test the bytes, not the working tree.** `core.autocrlf` silently
   stripped CRLF from two committed fixtures while the checks still passed.
   Byte-level cases read `git show :<path>`, not just the file.
3. **Never assume a naming or casing convention in a scan.** Three extent
   counts in `problems.md` were falsified that way.

Verdicts use the existing vocabulary: `PASS`, `FAIL`, `PARTIAL`,
`UNDECIDABLE`, `GUARD`.

## 7. Coverage

**46 cases + 21 edge cases against 39 requirements.** Every requirement has
at least one case (V-03 makes that itself a test).

Five cases are **already verified** ahead of implementation, because the
measurement was made while validating libraries: TC-18, TC-19, TC-26,
TC-32, TC-46.

Six are **GUARDs** rather than tests of our code — TC-E02, TC-E07, TC-E19,
TC-E20, plus TC-07 and TC-26. They assert facts about Unicode, the corpus,
git and PDF extraction that the design depends on. If one breaks, the
design is wrong, not the code.

### Not covered, and why

- **C-07** (114 truncated generations) — no test case exists, deliberately.
  Nothing in a test suite can detect that the script importing it was
  written by an interrupted response.
- **C-08** (validity) — TC-43 checks that a claim *has* a supporting check.
  It cannot check whether the claim is true. The circular `*****`
  marker would pass every case here.
- **Suitability of `TfidfVectorizer` driven from a lemma list** — still
  untested; the one library assumption from `libraries.md` §10 that the
  `monte_carlo_test` spike did not settle.
